Combinator API
--------------

- *Command-line arguments* - the values provided on the command-line
- *Parameter* - any value provided to the app from some external source (currently only from command-line arguments)
- *Option* - a parameter that may be provided anywhere in the command-line arguments.
    - A fixed string that starts with `-`, possibly also followed by zero or more values
- *Positional* - a parameter that may must appear at a certain position in the command-line arguments
- *Parser* - takes command-line arguments and produces some value of type `T`
- *Command* - a literal string that must appear at a certain position in the command-line arguments

Parsers
-------

- `option(name): Option<String?>`
    - matches `-n value` or `--name value`, null when not present
    - param `summary`
    - param `valueName`
- `option(name, unsignedInteger()): Option<Int?>`
    - matches `-n <int>` or `--name <int>`, null when not present
- `option(name, oneOf(mapping)): Option<T?>`
    - matches `-n <value>` or `--name <value>`, null when not present
- `option(name).required(): Option<String>`
    - matches `-n value` or `--name value`, must be present
- `option(name).boolean(): Option<Boolean>`
    - matches `-n` or `--name`, false when not present
- `option(name).boolean().required(): Parser<Unit>`
    - matches `-n` or `--name`, must be present
- `positional(name): Positional<String>`
    - matches 1 positional, must be present
    - param `summary`
- `positional(name, unsignedInteger()): Positional<Int>`
    - matches 1 positional, must be present and an unsigned integer
- `positional(name, oneOf(mapping)): Positional<T>`
    - matches 1 positional, must be present and one of the given choices
- `positional(name).oneOrMore(): Positional<List<String>>`
    - matches 1 or more positional, must be present
- `positional(name).zeroOrMore(): Positional<List<String>>`
    - matches 0 or more positionals, empty list when not present
- `command(text): Parser<Unit>`
    - matches the given text, must be present
- `anything(name): Positional<String>`
    - matches 1 argument - positional or option
    - param `summary`
- `anything(name).zeroOrMore(): Parser<List<String>>`
    - matches 0 or more arguments, empty list when not present
    - param `summary`
- `anything(name).oneOrMore(): Parser<List<String>>`
    - matches 1 or more arguments, must be present
    - param `summary`
- `params(producer): Parser<T>`
- `params(a, map): Parser<T>`
- `params(a, b, map): Parser<T>`
- `params(a, b, c, map): Parser<T>`
- `params(a, b, c, d, map): Parser<T>`
- `params(a, b, c, d, e, map): Parser<T>`
    - matches the parsers and maps the result. Options can appear in any order, positionals must appear in the order specified
    - param `summary`
- `action(action): Parser<Runnable>`
- `action(a, action): Parser<Runnable>`
- `action(a, b, action): Parser<Runnable>`
- `action(a, b, c, action): Parser<Runnable>`
- `action(a, b, c, d, action): Parser<Runnable>`
- `action(a, b, c, d, e, action): Parser<Runnable>`
    - matches the parsers as per `params()` and produces a `Runnable` that runs the function with the parse results as arguments.
    - param `summary`
- `oneOf(choices...): Parser<T>`
    - matches the parses and returns the first matching
- `app(name, parser): Parser<Runnable>`
    - adds application details to a parser
    - add help and completion actions
    - param `summary`
    - param `helpAction`, param `completionAction`

CLI app

- `parser.runApp(args)`
    - Color output
    - Usage summary
    - `-h`, `--help` options
    - `--completion` option
